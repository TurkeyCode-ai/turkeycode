Turkey = Turnkey

One prompt in.
A tested app out.

TurkeyCode is an open-source orchestrator for unattended development. Give it a prompt or a ticket and walk away. It runs a coding agent through research, planning, build, QA and code review, and you come back to tested, reviewed code.

npx turkeycode run "a habit tracker with streaks and reminders"
View on GitHub Quick start

Needs Node 20+, Git, and an agent CLI you are logged in to. Claude Code is the default.

What happens when you hit enter

  1. 01

    Scope

    It restates what it thinks you want. You correct it until the spec is right.

  2. 02

    Plan

    Research, then a plan: as many build phases as the work needs.

  3. 03

    Build

    One focused agent session per phase, on its own branch.

  4. 04

    Prove

    Fresh agents test it. Blockers get fixed and retested. Then it merges.

Nothing merges past a gate it did not clear. The gates are plain code, so the model cannot talk its way through.

Built to run while you are away

A chat session needs you in the chair. TurkeyCode does not. Once the spec is agreed, nothing in the run waits for you.

It does not stop to ask

When something is left open, it picks a default, writes down what it chose, and keeps going.

It checks its own work

Fresh agents that never saw the build test it and review it. What they find gets fixed and retested.

It picks up where it stopped

State is saved after every step. If a run is interrupted, turkeycode resume carries on from there.

The best way to use it: have your agent run it. Ask Claude Code, or whatever you use, to run TurkeyCode for you. It scopes the work with you in chat, starts the run, keeps an eye on it and reports back. The repo ships skills for exactly this.

It has worked a development backlog of 86 tickets this way: plan, build, review and push a branch for each, with a person only at the merge.

Case study: same model, with and without a spec

We asked Claude Code for a TI-84 style graphing calculator twice, one session each time. The only difference was the spec that TurkeyCode's research step wrote from the same one-line prompt, in under a minute.

With TurkeyCode's spec

One session, same model

$14.94

2,893 lines
Tests
205

Graphs, tables and matrices all worked. It shipped with 3 visible bugs.

Then the full pipeline. TurkeyCode's own run from that prompt took 1 h 47 min and left 226 passing tests. Its QA found 4 blockers along the way and had them fixed before anything merged.

The spec is what made the build work. The gates caught what the spec could not.

One prompt and one run each, so read it as a case study and not a benchmark. The full run took about three times as long as the session with the spec, and TurkeyCode does not yet record what a run costs.
